# Identical compliance records do not imply identical device conductance

Run `python examples/rram-compliance-witness/run.py`. This is an exact, dimensionless positive control. An ideal voltage source with a current limit is attached to a fixed passive resistor I = GV. With command V = 1 and limit |I| = 1, devices G = 2 and G = 4 have the same (commanded voltage, measured current) record (1, 1), but actual device-terminal voltages 1/2 and 1/4. At an unclipped V = 1/8 their currents are 1/4 and 1/2. Treating the source setting as terminal voltage predicts 1/8 in both and gives MAE 1/4; every one common prediction has MAE at least 1/8. A synchronized terminal-voltage record identifies both conductances exactly in this fixture.

The [Keysight B1500A User’s Guide, About SMU](https://go.keysight.com/us/en/assets/9018-01850/user-manuals/9018-01850.pdf) distinguishes source/monitor operation and compliance. The toy does not certify a hardware export, capture its waveform, tell which voltage is measured at the device, or model capacitance, contacts, switching or history. A compliance flag alone does not supply an actual terminal voltage. Under an independently certified ideal limiter and passive Ohmic state, the capped value provides at most a signed bound on the response at the commanded voltage, not an observed equality for it. If hitting compliance changes the state or source waveform, the toy inference is out of scope.

Compare command-only, appropriate inequality-censored, and synchronized-terminal models on complete held devices. Use actual terminal voltage for the primary held unclipped error and analyze clipped states separately. If actual voltage or compliance semantics are unverified, do not infer the missing I–V trajectory.
