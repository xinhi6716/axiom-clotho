# A recorded transient does not identify which pole belongs to the device

Run `python examples/instrument-device-pole-alias/run.py`. Two zero-state, time-invariant first-order filters commute under any common input. Swapping a device pole of 3/4 with a sensor pole of 1/4 thus gives the same training transient, including four step responses (3/16, 3/8, 135/256, 165/256). More waveforms passed through that *same* cascade do not resolve the ambiguity. A separate known-input test of the sensing path gives first outputs 3/4 or 1/4. After freezing the original candidate, replace only the sensing response by a calibrated pole of 1/2; wrong device attribution then produces a two-sample MAE of 5/16.

[Keithley’s Low Level Measurements Handbook, section 2.2 (including Figure 2-8)](https://www.tek.com/vn/documents/product-article/keithley-low-level-measurements-handbook---7th-edition) describes sensitivity to settling and the measurement network. This toy isolates pole ownership, not hardware parameters. Reference-path loading, range, aperture, and acquisition epoch must match; a path change that alters the device does not isolate the instrument. Reject transfer if reference identity is unsupported or a separately held trace fails. Quantization, nonlinear state changes and dynamic coupling can violate the simple cascade, so this is not a way to extract a physical pole from a single exported sweep.
